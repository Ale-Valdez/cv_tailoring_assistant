# CV Tailor - Documentación

Herramienta para adaptar un CV (PDF) a una oferta laboral sin inventar experiencia: analiza la oferta, compara con la experiencia real, detecta keywords ATS, propone cambios revisables y exporta un PDF generado desde HTML.

## Estado actual (dónde quedamos)

- Fecha de última actualización: 2026-11-13
- Fase: **Fase 5 hecha** (pulido). D26 sigue abierta y no bloquea.
- Hecho en la Fase 5, sección 4: `pnpm test:e2e` recorre la pantalla con Playwright (`tests/`). Importa un PDF, confirma el perfil, analiza una oferta, acepta la sugerencia y descarga el PDF. La API de esa corrida arranca con `E2E_FIXTURES=true` y sin `OPENAI_API_KEY`: el extractor, el analizador y el proponedor devuelven datos fijos que pasan el fabrication guard. La base es `cv_tailor_e2e`, aparte de la de uso. `@playwright/test` solo se importa desde `tests/`; el paquete `playwright` sigue solo en `renderer` (ADR-016). El PDF de la prueba lo responde un proceso del arnés en `POST /pdf`. `pnpm check` y el CI no la ejecutan: hace falta Postgres en marcha.
- Hecho en la Fase 5, sección 3: [06-uso.md](06-uso.md) explica el arranque y el recorrido hasta el PDF: `.env`, `pnpm compose`, `pnpm db:migrate`, importar y confirmar el perfil, pegar la oferta, revisar, previsualizar y descargar las versiones.
- Hecho en la Fase 5, sección 2: cada botón de la oferta dice la acción que está en curso. Analizar dice «Analizando…», la cobertura «Actualizando cobertura…», proponer «Proponiendo…» o «Actualizando propuesta…», aceptar «Aceptando…», guardar una edición «Guardando…», rechazar «Rechazando…», exportar «Exportando…» y la versión que se baja «Descargando…». Las demás quedan deshabilitadas con su rótulo habitual.
- Hecho en la Fase 5, sección 1: si el navegador no llega al servidor, o la respuesta no trae `{ code, message }`, la pantalla dice «No hay conexión con el servidor.» o «No se pudo completar la operación.». No muestra el texto del navegador (`Failed to fetch`, `HTTP 500`). El formulario de importar, confirmar, analizar, revisar y exportar se conserva. Si la API sí manda su mensaje, se muestra ese. El encabezado, cuando `/api/health` falla, dice «La API no responde.» y, si hay un detalle, lo agrega.
- Hecho en la Fase 4, sección 5: `ExportTailoredCv` arma el HTML de `profileForRender`, pide el PDF a `renderer` y lo guarda con `FileStorage` en `FILES_DIR` (en Compose, el volumen `files`). Cada exportación suma una versión. `POST /jobs/:id/proposal/export` la crea y `GET /jobs/:id/proposal/exports/:exportId` la descarga. Si queda una sugerencia `pending`, o la propuesta no está en `final`, responde 422 y no llama al renderer (ADR-025). La pantalla muestra el botón cuando ya no hay pendientes y lista las versiones anteriores.
- Hecho en la Fase 4, sección 4: `POST /pdf` de `apps/renderer` recibe el HTML y devuelve un PDF A4 con Playwright. Chromium se abre en la primera conversión y se reutiliza; `GET /health` no lo necesita. `PdfGenerator` lo implementa `adapter-pdf-renderer`, que llama a esa URL (`RENDERER_URL`; dentro de Compose, `http://renderer:3002`). En el host no se descargan los navegadores: el PDF se genera en la imagen de Compose.
- Hecho en la Fase 4, sección 3: `previewTailoredCv` pide la propuesta guardada y la pasa por `profileForRender` y la plantilla. `GET /jobs/:id/proposal/preview` responde ese HTML. La pantalla lo muestra al lado de las sugerencias, en un iframe sin scripts, y lo vuelve a pedir al aceptar, guardar una edición o rechazar. El texto que todavía está en el campo no entra hasta que se guarda.
- Hecho en la Fase 4, sección 2: `CvHtmlRenderer` lo implementa `adapter-cv-template`. El HTML es una página A4 de una columna, con el orden del CV de referencia: nombre, contacto, perfil, experiencia, proyectos, habilidades y educación (ADR-026). Los rótulos y los meses siguen el idioma del perfil. No hay foto, título bajo el nombre, grupos de habilidades ni idiomas hablados, porque el perfil no guarda esos datos.
- Hecho en la Fase 4, sección 1: `profileForRender` arma el perfil que se imprime desde la instantánea del `TailoredCV`. Aplica una sugerencia solo si está `accepted` o `edited` y el guard la marcó `valid`. `pending` y `rejected` dejan el texto original. Un bullet sustituye ese bullet, el resumen sustituye el resumen, y el orden de habilidades reordena las mismas entradas. El contacto no cambia y la instantánea guardada tampoco.
- Hecho en la Fase 3: `GenerateTailoringProposal` arma un `TailoredCV` para el perfil confirmado y la oferta guardada. Si la instantánea coincide con el perfil actual, no vuelve a llamar al modelo; si el perfil cambió, genera de nuevo, reemplaza las sugerencias y conserva el id. `proposeTailoringGraph` propone cambios de resumen, de bullet o de orden de habilidades. El fabrication guard es determinista, no llama a un LLM, y descarta un texto que introduce una herramienta, una empresa, una cifra o una fecha que el perfil no respalda (tampoco un alias de otro término: `Java` no sale de `JavaScript`). Reintenta hasta 3 veces y tira lo que sigue inválido. Al modelo viaja `profileForModel`, sin contacto (ADR-019), y el texto de la sugerencia no se traduce (ADR-022). Una sugerencia igual al original no se guarda. `POST /jobs/:id/proposals` genera, `GET /jobs/:id/proposal` lee y `POST /proposals/:id/suggestions/:suggestionId/review` acepta, edita o rechaza. Aceptar exige que el guard ya la haya marcado válida. Editar vuelve a correr el guard y, si el texto no se sostiene, no se guarda. Sin pendientes, el estado pasa a `final`. La propuesta queda en PostgreSQL (tabla `TailoredCV`, documento `jsonb`, con los `MatchResult` de esa comparación). La pantalla muestra el antes y el después. No se exporta mientras quede una sugerencia `pending` (ADR-025). Editar una sugerencia es un campo de texto; la vista previa será el HTML armado, sin editor visual libre (ADR-023). El PDF lo genera Playwright (ADR-024).
- Hecho en la Fase 2: `AnalyzeJobPosting` recibe texto pegado (ADR-021), rechaza vacío o de más de 50.000 caracteres y, si el hash ya está guardado, no vuelve a llamar al modelo. `analyzeJobGraph` clasifica requisitos y keywords y reintenta hasta 3 veces. El dominio unifica alias (`Postgres` y `PostgreSQL`, `JS` y `JavaScript`, sin mezclar `Java`) y `matchProfileToJob` marca cada requisito como cubierto, parcial o brecha con bullets de evidencia. Una habilidad sin bullet queda como brecha, con una nota. Las keywords dicen si están en el perfil y, por tanto, si se pueden incorporar. Si el idioma de la oferta y el del perfil difieren, el informe lo avisa y no traduce (ADR-022). `api` expone `POST /jobs/analyze`, `GET /jobs/current`, `GET /jobs/:id` y `GET /jobs/:id/match`. La oferta confirmada por el análisis queda en PostgreSQL (tabla `JobPosting`, documento `jsonb`). El informe no se persiste. La pantalla pega la oferta, muestra requisitos y keywords, y vuelve a comparar sin llamar al modelo.
- Hecho en la Fase 1: `packages/domain` tiene las entidades del modelo, validadas con Zod. El perfil distingue `needs_review` y `confirmed`. Confirmar exige nombre, idioma y los datos mínimos de cada bloque presente. `profileForModel` omite el contacto (ADR-019). Una sugerencia solo sale de `pending` (aceptar, editar o rechazar) y tiene que citar evidencia. Un `TailoredCV` solo admite un perfil ya confirmado. El fabrication guard quedó en la Fase 3. No se exporta mientras quede una sugerencia pendiente (ADR-025). `ImportProfileFromPdf` (ADR-020) lee el PDF con `unpdf`, rechaza archivos vacíos, de más de 10 MiB o sin texto seleccionable, quita emails y teléfonos antes del extractor, y devuelve un perfil `needs_review` sin bloque de contacto. `ProfileExtractor` lo implementa `extractProfileGraph` en `adapter-ai`: valida el borrador y reintenta hasta 3 veces. El ejemplo de `LLM_MODEL` es `gpt-6-luna` (ADR-011) y deja `LLM_TEMPERATURE` vacío: ese modelo solo acepta la temperatura por defecto. `api` expone `POST /profiles/import`, `POST /profiles/confirm`, `GET /profiles/current` y `GET /privacy`. El proxy de Next.js y Express limitan el PDF a 10 MiB (ADR-017). La pantalla pide confirmación antes de la primera llamada al proveedor y la guarda en el navegador (`cv-tailor.llm-consent`, ADR-019); después se corrige el perfil con formularios. Al confirmar, el perfil queda en PostgreSQL (una fila, documento `jsonb`, ADR-013) y `GET /profiles/current` lo vuelve a mostrar. El PDF original de la importación no se guarda. Los PDF exportados sí, desde la Fase 4. Detalle del modelo en `03-modelo-de-dominio.md`.
- Hecho en la Fase 0: monorepo pnpm (Node `24.19.0`, pnpm `12.18.0`) y Docker Compose con `web`, `api`, `renderer` y `db` (PostgreSQL 18, volumen `pgdata`). `api` y `renderer` responden `GET /health`. `web` reenvía `/api/*` a `api` y muestra si la API responde. `api` no publica puertos; en desarrollo el override sí. `api` sale al arrancar si faltan `LLM_PROVIDER` (`openai`), `LLM_MODEL`, `OPENAI_API_KEY`, `DATABASE_URL`, `FILES_DIR` o `RENDERER_URL`. Con `LANGSMITH_TRACING=true` también exige `LANGSMITH_API_KEY` y `LANGSMITH_PROJECT`. No hay código de trazas propio: LangSmith traza `extractProfileGraph` cuando el flag está activo (ADR-007). El volumen `files` está montado en `/data/files` (`FILES_DIR`). `FileStorage` guarda ahí los PDF exportados. El esquema de Prisma ya guarda el perfil confirmado. `packages/config` queda para cuando haya ESLint compartido.

- Arranque y recorrido de uso: [06-uso.md](06-uso.md). En corto: copiar `.env.example` a `.env`, completar `OPENAI_API_KEY` (`LLM_MODEL=gpt-6-luna` en el ejemplo), `pnpm install` y `pnpm compose`. Ese comando usa `docker-compose.dev.yml`: monta el repo y `web` corre `next dev`, así que un cambio de pantalla se ve sin reconstruir la imagen. Hace falta el `node_modules` del host. `pnpm compose:prod` es la imagen compilada, sin esa recarga. Antes de confirmar un perfil, analizar una oferta o proponer cambios, con Postgres en marcha: `pnpm db:migrate`. `pnpm dev` sigue sirviendo las apps en el host (lee `.env`). `pnpm check` ejecuta el typecheck, Vitest y la verificación de límites. El CI hace lo mismo. `pnpm test:e2e` recorre la pantalla sin llamar al modelo; hace falta Postgres publicado en el host y no entra en `pnpm check`. `dependency-cruiser` usa parser `swc` (`.dependency-cruiser.cjs`, ADR-016) porque la versión 18 no lee TypeScript 7, y no analiza los `*.test.ts`. `pnpm boundaries` también mira `tests/` y falla si el parser no pudo leer los fuentes.

## Resumen de la arquitectura

Monorepo TypeScript (pnpm workspaces) con arquitectura hexagonal. Backend Express (`apps/api`), frontend Next.js solo UI (`apps/web`), servicio `renderer` con Playwright y base PostgreSQL, todo con Docker Compose. LangChain y LangGraph orquestan los LLM dentro del adaptador de IA; el proveedor es OpenAI y se cambia desde el `.env` mediante una fábrica de modelos. LangSmith se activa solo con variables de entorno. Un solo usuario local, sin login.
